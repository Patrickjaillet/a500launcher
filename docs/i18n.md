# Translating A500 Launcher

All user-facing text lives in JSON files under `assets/i18n/`. There is no text in
the source code, so a translation is a data-only contribution.

## Files

- `en.json` is the reference. It defines every key and is never removed or renamed.
- Each other file is one language, named by its two-letter ISO 639-1 code
  (`fr.json`, `de.json`, ...). The app also accepts region codes (`pt-BR.json`).

## Adding or updating a language

1. Copy `en.json` to `<code>.json`.
2. Translate every value. Keep the keys exactly as they are.
3. Set `language.name` to the language's own name (e.g. `"Français"`), because it is
   shown in the language selector.
4. Keep every `{0}`, `{1}` placeholder. They are filled in at runtime with values
   such as a file name or a count. You may reorder them, but all of them must appear.
5. Leave technical tokens untranslated: file dialog filters keep their
   `Name|*.ext|Name|*.ext` structure, and `dialog.about.email` / `dialog.about.website`
   are not translated.
6. Run the check:

   ```
   pwsh tools/i18n-check.ps1
   ```

   It reports missing keys, unknown keys, and placeholder mismatches. It must print
   `i18n-check: OK`.

## What the app does at runtime

- On first run the launcher picks the OS UI language if a matching file exists,
  otherwise English.
- The user can override this in Settings. The choice is stored as `LanguageCode`
  and applied on the next start.
- Any key missing from a language falls back to the English value, then to the key
  name itself, so a partial file never crashes the app.
